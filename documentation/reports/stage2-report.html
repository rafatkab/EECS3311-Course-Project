Stage 2 Implementation Report

AI-powered Study Planner | EECS 3311 | Rafat Kabir
Progress draft: F01–F08 and UC-11, November 8, 2026.

1. Overview and status

Students can create courses, upload materials, generate summaries, extract concepts, ask questions about their materials, generate personalized study schedules, study AI-generated flashcards, and generate and attempt quizzes through a Vaadin GUI or Java CLI. Spring Boot stores courses, materials, summaries, concept sets, chat history, profiles, plans, flashcard decks, quizzes, attempts, and calendar events in H2. F03 uses local Ollama; the HTTP adapter also supports hosted OpenAI-compatible providers.

F01–F08 and UC-11 are implemented. F10 has event storage and plan synchronization; its full interface remains pending. F09 and course editing/deletion remain pending. Authentication supports one locally configured account and does not count as a project feature.

2. Feature-to-implementation mapping

F01: Course Creation. Deterministic. References: Stage 1 Task 1.2 F01, UC-01, SD01, and Task 4 F01. Students enter a name, description, start date, and end date. The system validates the input, saves an owned course, and displays it on the dashboard. Video: pending.

PartFiles, responsibilities, and key methods
GUIfrontend/.../views/MainView.java: showSignIn, showDashboard, openCourseForm, refreshCourses, and renderCourses handle sign-in, forms, errors, and course cards. themes/study-planner/styles.css styles the UI.
API clientfrontend/.../course/CourseApi.java: createCourse/viewCourses call the backend. CourseApiFactory.connect creates a client for each signed-in view. Frontend Course and CreateCourseRequest records carry API data.
REST APIbackend/.../course/CourseController.java: createCourse, viewCourses, and getCourse expose POST/GET /api/courses and GET /api/courses/{id}.
Application and domainCourseService coordinates creation and retrieval. User.createCourse/viewCourses create and retrieve owned courses. Backend Course validates domain data; CreateCourseRequest validates API fields.
StorageCourseRepository defines storage operations. JdbcCourseRepository.save/findByOwner/findByIdAndOwner use SQL. schema.sql defines the table. H2 files persist under backend/data/.
Authentication and errorsSecurityConfiguration verifies credentials; CsrfController.token supports protected writes. ApiExceptionHandler handles invalid requests and storage failures. The authenticated student determines course ownership.
CLIcli/StudyPlannerCli.java: main/run provide create, list, and help using the same authenticated API.

Flow: form or CLI → CourseController → CourseService → User.createCourse → CourseRepository → H2. The GUI then reloads the saved course list. Failed submissions show errors and preserve form input.

All four fields are required. Names allow 120 characters; descriptions allow 2000. Text is trimmed, and end dates must be on or after start dates. Same-day courses and duplicate names are allowed. Course queries are restricted to their owner.

F02: Upload Learning Materials. References: Stage 1 Task 1.2 F02, UC-02, SD01, and Task 4 F02. Open an owned course, select files, and view the saved materials and extracted text. Upload/validation/text extraction are deterministic; the planned AI processing belongs to later features. Video: pending.

PartImplementation and key methods
GUI / clientMainView.openCourse opens CourseMaterialsPanel; upload, refreshMaterials, and viewText show results and errors. Each file offers View text and Download original. CourseApi.uploadMaterial/listMaterials/materialContent/downloadMaterial call the authenticated API.
API / serviceCourseController.uploadMaterial/listMaterials/materialContent/downloadMaterial delegate to MaterialService, which verifies course ownership before access.
Domain / parsingCourse.addMaterial creates LearningMaterial; getContent exposes extracted text. MaterialParser.parse checks filenames and parses PDF, DOCX, or UTF-8 TXT using PDFBox, POI, or UTF-8 decoding.
Storage / CLIMaterialRepository and JdbcMaterialRepository save metadata, original BLOB, and extracted text together. StudyPlannerCli adds upload, materials, and content.

Rules: up to 10 files, 10 MiB each; unsupported, empty, corrupt, encrypted, or text-free files are rejected. No OCR is provided. Text is limited to 1,000,000 characters, PDF to 500 pages, and expanded DOCX to 20 MiB/1000 entries. API batches roll back on any failure; GUI files upload independently. Originals and text survive restarts.

F03: Document Summarization. AI-based. References: Stage 1 F03, UC-03, SD02 summary branch, and Task 4 F03. Select Summarize document; the agent summarizes source sections, synthesizes them when needed, resolves selected source-excerpt IDs to verified quotations, and saves the result. View saved summary reuses it; regeneration explicitly requests a replacement. CLI: summarize, summary, regenerate-summary. Video pending.

PartImplementation
GUI / APIfrontend/.../views/SummaryActions runs background requests; CourseApi.summarize/viewSummary call backend/.../resource/SummaryController. Progress and safe errors remain visible while inference runs.
Agent / resourceCourse.generateStudyResource calls StudyAssistantFacade.summarize. ContentAgent.summarize plans sections and validates responses from AIEngine.generate. StudyResourceFactory.createResource constructs Summary, extending StudyResource; view returns its text.
StorageSummaryService verifies ownership, guards concurrent generation, and checks the source hash. SummaryRepository/JdbcSummaryRepository save the latest summary, evidence, model, and usage. Failed regeneration preserves the previous result.

F03 accepts 40–32,000 source characters. Generation has schema-constrained output, bounded calls/time, and one repair attempt for invalid results. Missing setup, provider failures, insufficient text, invalid output, and timeouts return errors without saving. Quotations must match the source; factual accuracy still needs human review.

F04: Concept Extraction. Implemented, AI-based. References: Stage 1 F04, UC-04, SD02 concept branch, Task 4 F04, and original UML. Select Extract Concepts for an uploaded document or uploaded section; a list shows important topic names, explanations, and supporting source quotations. View saved concepts and Regenerate concepts provide reuse and replacement. Video pending.

PartImplementation and collaboration

Agent / patternsCourse.generateStudyResource → StudyAssistantFacade.extractConcepts → ContentAgent.extractConcepts → singleton AIEngine.generate. The agent reads LearningMaterial.getContent, plans sections, extracts concepts, and consolidates multi-section results. Validation / storageStructured output requires 1–10 concepts with names, explanations, and valid source-excerpt IDs. Concept names may paraphrase the source; readable source sentences and long-sentence tails are available as evidence, with dense lists grouped into contiguous windows. ConceptSetRepository/JdbcConceptSetRepository atomically save the latest set in H2; failed regeneration preserves it.

F04 shares F03’s 40–32,000-character, 14-call, 180-second, and provider limits. It operates on a selected uploaded material, including a separately uploaded section; course-section management and whole-course extraction are not included. Exact quotations do not guarantee explanation accuracy or semantic uniqueness.

F05: Question Answering Over Materials. Implemented, AI-based. References: Stage 1 F05, UC-05, SD02 question branch, Task 4 F05, and original UML. Open a course, enter a question in Course chat, and send it. The agent finds relevant course passages, asks Ollama for an answer, checks its source references, and saves the exchange. Expand a source to read its quotation or open the document text. Video pending.

PartImplementation and key methods
GUI / API / CLICourseChatPanel shows progress, saved messages, wrapped answers, source quotations, and errors through CourseApi.askQuestion/chatHistory. ChatController exposes POST/GET /api/courses/{courseId}/chat. CLI: ask and history.
Domain / AICourse.askQuestion → CourseChat.askQuestion → StudyAssistantFacade.answerQuestion → ContentAgent.answerQuestion → AIEngine.generate. CourseContextRetriever.retrieve ranks passages using words in the question and recent conversation. The model receives up to six matching passages. Follow-up questions can also use short excerpts from two recent exchanges; new topics start without earlier answers. F05 reuses Facade and Singleton.
Storage / validationChatService checks ownership, question length, and concurrent requests. ChatRepository/JdbcChatRepository save complete ChatTurn records in H2. CourseChat.viewHistory returns saved exchanges. Citations include material ID, filename, text offsets, and the original quotation. ChatAnswerValidator.isUnfinished detects dangling introductions and empty list items. History loads in pages of 50, with older messages available.

Questions allow 1–1000 characters. Chat searches up to 50 materials and 1,000,000 extracted characters per course; larger courses get an error. Invalid or visibly unfinished AI output gets one correction attempt. Introductions without the promised content and empty list items are not saved. Failed requests preserve the question in the GUI and leave history unchanged. Insufficient-context responses are saved without citations. Broad questions such as “Tell me about this course” use passages from across the uploaded materials. For specific questions with no matching passages, the system declines without a model call; the GUI labels this as Course search. Word matching can miss relevant passages, and valid source references do not guarantee correct answers.

F06: Personalized Study-Plan Generation; UC-11: Maintain Study Profile. Implemented, hybrid. References: Stage 1 F06, UC-06/UC-11, SD03, Task 4 F06, and original UML. Open Study plan and availability, save a profile, add busy times or quiz/exam dates, then choose plan dates and session count/duration. The AI recommends topics and activities; Java finds valid times and saves the plan and calendar sessions. Video pending.

PartImplementation and key methods
GUI / CLI / APIStudyPlanningPanel edits availability, preferences, habits, and events, then displays priorities, sessions, and source quotations. CourseApi calls PlanningController. CLI adds profile, save-profile, plan, generate-plan, events, add-event, and remove-event.
Profile / orchestrationStudyProfile.updateAvailability/updatePreferences validate the shared weekly profile. PlanningService checks ownership, dates, material limits, and available time. Course.generateStudyResource calls StudyAssistantFacade.generateStudyPlan.
AI / scheduling / factoryPlanningAgent.generateStudyPlan uses source excerpts, profile data, upcoming dates, and optional assessment notes through the singleton AIEngine.generate. It validates topics, priorities, activities, and source IDs, with one repair attempt. StudyScheduler.allocate chooses all times. StudyResourceFactory.createResource creates StudyPlan and StudySession; getSessions exposes the schedule.
Storage / ObserverPlanningRepository stores profiles, latest plans, and events in H2. PlanPersistence.save attaches the Calendar observer and calls StudyPlan.notifyObservers. Calendar.update replaces the course's generated events. Plan and calendar changes commit together; failure preserves both previous records.

Weekly study minutes are shared across courses and must fit non-overlapping availability windows. Plans contain 1–30 sessions of 15–180 minutes over 1–56 days, within course dates and no earlier than today in the profile's time zone. Sessions avoid calendar conflicts, respect weekly budgets, and finish before the earliest upcoming quiz/exam in the selected period. Changing profile/events affects the next generated plan. Assessment results can be entered as notes; automatic quiz-result integration waits for F09. Topic quality needs source review. Limits remain 50 materials / 1,000,000 extracted characters. Topic discovery checks up to six passages, with at most two calls per passage and a shared 180-second limit. Up to 12 specific topics are collected; there is no fixed two-topic limit.

F07: Flashcard Generation. Implemented, AI-based. References: Stage 1 F07, UC-07, SD04 flashcard branch, Task 4 F07, and original UML. Expand Flashcards in a course, choose a maximum and optional materials/topic, then generate. Click a question or Show answer to reveal the answer and sources; previous/next cards hide the next answer. Saved decks reopen without AI. Video pending.

PartImplementation and key methods
GUI / API / CLIFlashcardPanel offers material selection, a 1–20 card maximum, optional topic focus, answer reveal, navigation, and saved history. CourseApi.generateFlashcards/flashcardDecks/flashcardDeck call FlashcardController: POST/GET /api/courses/{id}/flashcards and GET .../{deckId}. CLI adds flashcards, decks, and deck.
Planned class flowCourse.generateStudyResource → StudyAssistantFacade.generateFlashcards → AssessmentAgent.generateFlashcards → AIEngine.getInstance/generate → StudyResourceFactory.createResource → FlashcardDeck. LearningMaterial.getContent supplies the source text; FlashcardDeck.viewCards supplies cards through the API getter. Reuses Facade, Singleton, and Simple Factory.
Validation / storageFlashcardService checks ownership, selected files, size, and concurrent generation. AssessmentAgent selects excerpts, generates batches of up to three, validates questions/answers/source IDs, removes duplicate questions, and permits one repair per batch. FlashcardRepository stores complete decks in H2 flashcard_decks. History pages contain 25 decks; failed generation preserves previous decks.

The maximum is 1–20 cards; the model may return fewer useful cards instead of padding. Empty material selection uses all course files. Selecting separately uploaded sections limits the source; a topic focus narrows passage matching. There is no separate section-management feature. Limits: 50 materials, 1,000,000 extracted characters, six 700-character excerpts, 40 model calls, and 180 seconds. Answers must copy a sentence or short phrase from a cited excerpt (ignoring case and repeated whitespace). This rejects invented answers even when the model gives a valid source ID. Questions are AI-written; their relevance and semantic uniqueness still need review. Saved decks are snapshots.

F08: Quiz Generation. Implemented, AI-based. References: Stage 1 F08, UC-08, SD04 quiz branch, Task 4 F08, and original UML. Expand Quizzes, choose count/difficulty/topics/materials and optional types, then generate. Start a quiz, save a draft, reopen it, and finish to review expected answers and source quotations. Automatic grades/feedback remain F09. Video pending.

PartImplementation and key methods
GUI / client / CLIQuizPanel, QuizData, and CourseApi provide generation, saved history, mixed questions, draft/resume, finish, review, progress, and errors. CLI adds generate-quiz, quizzes, quiz, start-quiz, quiz-attempts, quiz-attempt, save-quiz, and finish-quiz.
Planned class flowCourse.generateStudyResource → StudyAssistantFacade.generateQuiz → AssessmentAgent.generateQuiz → QuizGenerator → singleton AIEngine.generate → StudyResourceFactory.createResource → Quiz. Quiz.startQuiz returns the public questions used by the API. Reuses Facade, Singleton, and Simple Factory; Quiz is the fifth product.
Generation / evidenceThe agent retrieves course passages and asks the model to select a missing phrase from each source fact and optional MCQ distractors. Java builds a fill-in-the-blank question, checks that its key restores the original statement, rejects repeated question stems and choices, and shuffles MCQ choices. One repair per fact; the exact question count must pass before saving.
API / storage / attemptsQuizController/QuizService/QuizRepository enforce ownership and store quizzes/attempts in H2. POST/GET /api/courses/{id}/quizzes generate/list; quiz and attempt routes read/start/save/finish. Draft responses omit keys; completed attempts permit answer review. Version checks prevent stale saves. Earlier quizzes remain unchanged on generation failure.

Inputs: 1–20 questions, EASY/MEDIUM/HARD, optional topics (500 characters), and SHORT_ANSWER/MULTIPLE_CHOICE preferences; empty types default to short answer. Selected files represent uploaded sections. Limits: 50 materials / 1,000,000 characters, six 700-character excerpts, 40 calls / 180 seconds. Unusable facts are skipped while the bounded generation budget remains. Draft answers allow 4000 characters; finishing requires all answers and freezes the attempt. Quiz history and recent attempts show 25 entries per page/list. Difficulty guides the phrase selected for the blank. Distractor plausibility, ambiguity, relevance, and semantic difficulty still need review.
